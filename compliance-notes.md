met for contrast on all body text, headings and prompt text. The two places
that sit at AA rather than AAA are named in section 3.

## 4. PDF accessibility

Every PDF this course shipped before today was Chrome print-to-PDF, which writes
no structure tree. Those files opened correctly and reached a screen reader as
unstructured text: no headings to navigate by, no list or table semantics, no
alt text, and no guaranteed reading order. Five of the seven were untagged.

They are rebuilt with WeasyPrint targeting **PDF/UA-1**, by
`tools/make_pdf.py`. Pages that build themselves in JavaScript are rendered in
headless Chromium first and the settled DOM is handed over, so the PDF matches
what a student sees.

| `BIO005-Fall2026-Competencies-by-Week.pdf` | 31 | yes | yes | en-US | H1 x1, H2 x4, H3 x15 | 0 of 0 |
| `BIO005-Fall2026-Competency-Packet.pdf` | 18 | yes | yes | en-US | H1 x1, H2 x2, H3 x5 | 0 of 0 |
| `BIO005-Fall2026-Syllabus.pdf` | 17 | yes | yes | en-US | H1 x1, H2 x16, H3 x16 | 0 of 0 |
| `BIO005-Week1-Competencies.pdf` | 6 | yes | yes | en-US | H1 x1, H2 x2, H3 x12 | 2 of 2 |
| `BIO005-Week1-NoteSheet.pdf` | 6 | yes | yes | en-US | H1 x1, H2 x12 | 0 of 0 |
| `BIO005-Week2-Graphing-Worksheet.pdf` | 5 | yes | yes | en-US | H1 x1, H2 x4 | 3 of 3 |

Every file above: `/MarkInfo /Marked true`, a `/StructTreeRoot`, `/Lang en-US`,
a title in the document catalog, and `/ViewerPreferences /DisplayDocTitle true`
so a reader announces the title rather than the filename.

Three problems found and fixed during this pass, each named because each would
have shipped silently:

1. **Inline SVG never reached the tag tree.** The three figures on the Week 2
   graphing worksheet carried `role="img"` and a full `aria-label` on screen,
   and WeasyPrint emitted them as bare marked content with no `/Figure` and no
   `/Alt`. A student on a screen reader would have met three undescribed
   pictures with six questions about them. The build now converts each described
   SVG to an `img` carrying the same text in `alt`, which produces `/Figure`
   with `/Alt`. Verified: 3 of 3 figures on the worksheet, 2 of 2 on the Week 1
   competency page.
2. **The note sheet shipped two H1s.** The on-screen page heading was being
   tagged alongside the sheet's own runner. The printed artifact is now scoped
   to the sheet pages only.
3. **The Week 2 worksheet skipped from H1 to H3.** The figure titles are now H2.

The old untagged files are moved to `_superseded/` rather than deleted, and
`syllabus-fall2026.html` now links the tagged build.

## 5. Keyboard navigation

Verified on `week-01-competencies.html` and a generated page,
`week-08-competencies.html`, as the largest at 25 competencies.

Tab order: skip link, brand mark, Course home, the five jump squares in order,
then each competency's prompt A and prompt B in document order. Nothing is
reachable that is not operable, and nothing operable is unreachable. No positive
`tabindex` anywhere. No keyboard trap.

Space toggles a prompt checkbox. Ticking B unticks A, which is the intended
one-prompt-per-competency rule, and the change is announced through the
progress bar's `aria-live` region rather than being visual only.

The horizontally scrolling template region on the note sheet carries
`tabindex="0"` and a `role="region"` with an accessible name, so it can be
scrolled from the keyboard.

## 6. Screen reader testing

**Automated only, so far.** The accessibility tree was walked in headless
Chromium for all fifteen competency pages and the note sheet, checking landmarks,
heading order, accessible names on every link and control, label association,
and live region wiring. All fifteen pass. The PDF structure trees were audited
directly with pikepdf and are reported in section 4.

**What has NOT been done, and is owed before this is called complete:**

- A pass with **VoiceOver on macOS Safari**, which is what a Mac student most
  likely uses.
- A pass with **NVDA on Windows Firefox**, which is what a Windows student most
  likely uses.
- Opening the six PDFs in **Adobe Acrobat's Accessibility Checker** and in a
  real reader, because a structure tree that audits clean can still read badly.

An automated pass proves the semantics are present. It does not prove the page
is usable, and this document should not be read as claiming it does.

The two files added September 7, 2026 were checked the same way: heading
order with no skipped levels, every image carrying alt text, no link with an
empty accessible name, a skip link ahead of the content on the discussion
page, and full keyboard reach with a visible focus ring. Both still need the
human VoiceOver and NVDA passes in limitation 1.

The second batch of September 7 files was checked the same way. On
`course-grid.html` each item's two boxes sit in a `role="group"` labeled by
the item name, so a screen reader announces "Lab, Started checkbox" rather
than an orphan "Started"; 71 groups, no unlabeled input. The trend chart on the retired
`practice-log.html` was `aria-hidden` with a sentence beneath it stating the
same numbers in words; that pattern is worth keeping if a chart is ever added
to the generator's own log.

The assistant was also audited on September 7, 2026 against the current course
model. Retired facts found and corrected: note sheets at 20 percent, book
problems at 15 percent, labs at 15 percent, three midterm windows, five grade
components, a Scholar Points bank, a placeholder grade weight in the
attendance answer, and a `loop` keyword that answered every feedback loop
question with a note about lab practice items. Two standalone pages carried
frozen copies of the assistant and its dock and were re-inlined from source by
`tools/reinline_hootie.py`; on both, a guard was stopping the schedule and the
248 answer bank from ever loading, so the assistant replied "I cannot see the
schedule from this page" to every question asked on them.
